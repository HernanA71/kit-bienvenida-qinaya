Documentación de API

Estructuras de datos requeridas para el Dashboard Analítico de Qinaya

Este documento detalla la estructura JSON que el Dashboard debe consumir desde la API de Qinaya para renderizar las gráficas y tablas. Se requieren 4 endpoints principales.

URL base de la API (producción): https://panel.qinaya.co/api2/

Nota para el desarrollador: actualizar la variable API_BASE_URL en dashboard.js (línea 24) con la URL base anterior. Los endpoints se invocan como archivos .asp (por ejemplo, organizations.asp).

Parámetros comunes (GET)

Los endpoints que filtran datos comparten estos parámetros en la URL:

org     = OrgId numérico de la organización (ej. 28)
since   = Fecha inicial del rango, formato YYYY-MM-DD (obligatorio en usage, computers y websites)
until   = Fecha final del rango, formato YYYY-MM-DD (obligatorio en usage, computers y websites)
site    = Nombre del colegio/sede (TeaName). Opcional. Si se omite, incluye todos los colegios de la org.

Ejemplo: usage.asp?org=28&since=2026-06-01&until=2026-06-30&site=Colegio%20Manuel%20Socorro

Nota: el colegio se identifica por nombre (site), no por id numérico. Los nombres deben coincidir exactamente con los devueltos en /organizations.

1. Lista de Clientes y Colegios /organizations.asp

Propósito: Alimenta el filtro principal (Secretarías, Gobernaciones, etc.) y el sub-filtro de colegios/sedes.

Parámetros: ninguno.

Estructura esperada (Array de objetos JSON):

[
  {
    "id": "28",
    "name": "Secretaría de Educación de Bogotá",
    "isPrimary": true,
    "sites": [
      "Colegio Manuel Socorro",
      "Colegio Virginia Gutiérrez de Pineda",
      "Colegio El Salitre"
    ]
  },
  {
    "id": "31",
    "name": "Gobernación Tolima",
    "sites": ["Espinal", "Suárez"]
  }
]

Campos:

  • id — OrgId (entero, serializado como string).
  • name — Nombre de la organización.
  • isPrimary — Opcional. La API lo envía en la primera organización de la lista.
  • sites — Array de nombres de colegios (TeaName), ordenados alfabéticamente.

2. Histórico de Uso /usage.asp

Propósito: Alimenta la gráfica principal de horas de uso local vs. VM a lo largo del tiempo.

Parámetros (GET): ?org={OrgId}&since={YYYY-MM-DD}&until={YYYY-MM-DD}&site={nombre_colegio}

site es opcional. Todas las horas están en horas (no minutos).

Estructura esperada: Un objeto con 4 arreglos paralelos de igual longitud (un punto por día con datos en el rango).

{
  "labels": ["lun, 1 jun", "mar, 2 jun", "mié, 3 jun", "jue, 4 jun"],
  "localUsage": [3160.95, 4291.13, 3320.58, 3394.1],
  "vmUsage": [0, 0, 0, 0],
  "totalUsage": [3160.95, 4291.13, 3320.58, 3394.1]
}

Campos:

  • labels — Etiqueta del día en español (ej. "lun, 24 jun").
  • localUsage — Horas de uso en equipo local / STB.
  • vmUsage — Horas de uso en máquina virtual.
  • totalUsage — Horas totales del día (suma de uso registrado).

3. Detalle de Equipos /computers.asp

Propósito: Llena la tabla de detalle inferior y la gráfica de dona (Virtual vs. Local) calculando sumatorias.

Parámetros (GET): ?org={OrgId}&since={YYYY-MM-DD}&until={YYYY-MM-DD}&site={nombre_colegio}

site es opcional. Todas las horas están en horas.

Estructura esperada (Array de objetos):

[
  {
    "id": "RE0503",
    "site": "Colegio Virginia Gutiérrez de Pineda",
    "status": "online",
    "localHours": 77.69,
    "vmHours": 0,
    "totalHours": 77.69,
    "topApp": "Chrome"
  },
  {
    "id": "RE0504",
    "site": "Colegio Virginia Gutiérrez de Pineda",
    "status": "online",
    "localHours": 45.2,
    "vmHours": 48.04,
    "totalHours": 93.24,
    "topApp": "QinayaDeskLauncher"
  }
]

Campos:

  • id — Nombre de la computadora (ComName), no un código interno.
  • site — Nombre del colegio (TeaName).
  • status — Por ahora siempre "online".
  • localHours / vmHours — Horas en el rango de fechas, desglosadas por tipo de uso.
  • totalHours — Horas totales en el período.
  • topApp — Aplicación con más tiempo de uso en esa máquina en el período.

4. Sitios Web Más Visitados /websites.asp

Propósito: Llena la gráfica de barras horizontales de dominios más usados.

Parámetros (GET): ?org={OrgId}&since={YYYY-MM-DD}&until={YYYY-MM-DD}&site={nombre_colegio}

site es opcional. Devuelve los 10 dominios con más tiempo de uso en el período.

Estructura esperada (Array ordenado alfabéticamente por dominio):

[
  { "name": "docs.google.com", "visits": 330.57, "category": "General" },
  { "name": "www.google.com", "visits": 999.6, "category": "General" },
  { "name": "www.youtube.com", "visits": 888.31, "category": "General" },
  { "name": "www.tinkercad.com", "visits": 883.46, "category": "General" }
]

Campos:

  • name — Dominio visitado (MweDomain).
  • visits — Tiempo total de uso en horas (no cantidad de visitas). El nombre del campo se mantiene por compatibilidad con el frontend.
  • category — Por ahora siempre "General". La categorización se implementará en una fase posterior.
